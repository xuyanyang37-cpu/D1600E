# Dell/Delta D1600E 00.3D.67 — I2C1 ISR 深入静态分析

## 范围与输入

- 固件载荷：`095HR5_190AD_00.3D.67_extracted(1).bin`
- 程序映像：`D1600E_00.3D.67_dspic_program_4byte_slots.bin`
- 24-bit 指令按 4-byte slot 读取；PC 每条指令递增 2。
- 本报告是静态反汇编/控制流分析，不执行固件、不连接电源、不写 PMBus 寄存器。

## 1. 复位入口和启动链

| PC | 原始指令 | 解码/说明 |
|---|---:|---|
| `0x000000` | `040C00` + `000000` | `GOTO 0x000C00` |
| `0x000C00` | `040C40` + `000000` | `GOTO 0x000C40` |
| `0x000C40` | `22874F` | `MOV #0x2874,W15`，设置栈指针 |
| `0x000C42` | `22BF0E` | `MOV #0x2BF0,W14` |
| `0x000C48` | `07000C` | `RCALL 0x000C62` |
| `0x000C4E` | `07001F` | `RCALL 0x000C8E` |
| `0x000C5A` | `027C34` + `000000` | `CALL 0x007C34` |
| `0x000C5E` | `DA4000` | `BREAK` |
| `0x000C60` | `FE0000` | `RESET` |

`0x000C40` 是复位链到达的启动代码入口。`0x007C34` 是一个初始化/服务调用序列入口，连续调用多个内部例程（例如 `0x7BDC`、`0x76CA`、`0x7D46`、`0x6464`、`0x7824`、`0x6A14`、`0x5DE2`、`0x7160`、`0x7244`、`0x620A`、`0x511E`、`0x4678`、`0x4070`、`0x50C6`、`0x68E0`、`0x6C44`、`0x4AF2`）。这些子程序的外设功能仍需逐个追踪，当前不按名称臆测。

## 2. I2C1 从机中断已获得强证据

dsPIC33FJ64GS606 数据手册的 I2C1 SFR 表给出：`I2C1RCV=0x0200`、`I2C1TRN=0x0202`、`I2C1BRG=0x0204`、`I2C1CON=0x0206`、`I2C1STAT=0x0208`、`I2C1ADD=0x020A`。`I2C1STAT` 中 `D_A` 位为 bit 5，`R_W` 位为 bit 2。

固件标准/备用向量的 SI2C1 入口均指向 `PC=0x006FA2`。在 ISR 中观察到：

| PC | 原始指令 | 解释 |
|---|---:|---|
| `0x006FB8` | `BFC208` | `MOV I2C1STAT,W0`（直接文件寄存器读取） |
| `0x006FBA` | `A32800` | `BTST.Z W0,#2`，测试 `I2C1STAT.R_W` |
| `0x006FBC` | `3A0011` | `BRA NZ,0x006FE0`，按读/写方向分支 |
| `0x006FC0` | `B3C201` | 字节文件寄存器读取编码；地址字段为 `0x0201`，与 `I2C1RCV` 低字节位置相符 |
| `0x006FE6` | `BFC208` | 再读 `I2C1STAT` |
| `0x006FE8` | `A35800` | `BTST.Z W0,#5`，测试 `I2C1STAT.D_A` |
| `0x006FEA` | `320011` | `BRA Z,0x00700E`，按地址/数据阶段分支 |
| `0x00700E`、`0x007014`、`0x007026`、`0x00702C` | `BFC208` | 多次读取 I2C1 状态并继续分支 |

因此可以确认：`0x006FA2` 不只是一个“碰巧存在”的向量，它的指令流直接检查 I2C1 状态寄存器的 `R_W` 和 `D_A` 位，并读取 `I2C1RCV` 对应的接收数据寄存器位置。这是固件实现 I2C1 从机事务状态机的强证据，也与 PMBus 使用 I2C 物理层的方式吻合。

**边界：**这还不能证明具体 PMBus 命令表、PEC 算法、器件地址寄存器的配置值或电压/风扇写命令。用户台架报告的 7-bit 地址 `0x58` 是独立实测信息；当前固件片段尚未读出 `I2C1ADD` 的初始化值。

## 3. I2C1 ISR 调用链

在 `0x006FA2` 及其后续控制流中观察到以下内部调用：

- `RCALL 0x00328C`（从 `0x006FCA` 一带进入）
- `RCALL 0x00332A`（从 `0x006FDA` 一带进入）
- `RCALL 0x00280A`（从 `0x007022` 一带进入）
- `RCALL 0x006F6A`（从 `0x007032` 一带进入）

`0x00328C` 内部还调用 `0x00323C`、`0x006F64`、`0x006F5E`、`0x0035D2`、`0x003602`；`0x00280A` 也调用 `0x00332A`、`0x00145A`、`0x0035D2`、`0x003602`。这些函数是下一步追踪 PMBus 接收缓冲区、命令分派和响应数据路径的重点。

`0x00332A` 包含对若干 RAM/间接地址的访问及 XOR 运算，但仅凭 XOR 不能断定它就是 SMBus PEC/CRC。必须继续追踪其输入、输出和调用者，才能确定它的算法用途。

## 4. ADC / UART / Timer 中断线索

- ADC Pair 0 向量目标 `0x007404`，ADC Pair 1 目标 `0x00740A`；`0x00740A` 开始后保存寄存器并访问多个数据区，含多组阈值比较和调用 `0x0035D2`、`0x003602`、`0x003FF8`。目前只能确认 ADC 中断后有数据处理/条件判断，不能给每个通道贴上电压、电流或温度标签。
- UART2 RX 向量目标 `0x005594`；代码中出现 `0x127C`、`0x127A`、`0x1263` 等缓冲区/状态常量，并调用 `0x003342`、`0x005A86`。它是独立串行接收路径；是否用于调试、内部通信或其他接口仍未确认。
- Timer1 向量目标 `0x007BB4`，其 ISR 调用 `0x00481C` 与 `0x007C5A`；Timer2、Timer3、Timer5 也有非默认中断入口。

## 5. 下一步待完成

1. 反汇编 `0x00328C`、`0x00332A`、`0x00280A` 的完整调用者/被调用者，确定收发缓冲区和命令码流。
2. 查找 I2C1 初始化对 `I2C1ADD`、`I2C1CON`、`I2C1BRG` 的写入，验证固件地址与用户台架 `0x58` 是否一致。
3. 找到 CRC/PEC 计算的输入字节序、地址字节处理、初值和多项式；未完成前不把任何 XOR 例程称为 PEC。
4. 追踪 ADC ISR 与采样缓存的交叉引用，再映射到实际通道/板上分压与电流检测网络。
5. 追踪风扇转速/控制路径，区分 PWM、TACH 输入捕获和 PMBus READ_FAN_SPEED/命令响应。

## 6. 安全说明

本报告只做离线静态分析。固件头部标识为 `095HR5A00` / `00.3D.67`，不能据此认定它与用户板上 `95HR5A05PS` 完全兼容；在 MCU 型号、板号和映像匹配关系未核实前，不建议刷写。当前不建议对未知厂商寄存器进行试写。
